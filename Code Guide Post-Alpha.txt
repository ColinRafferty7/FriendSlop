Code Guide Post-Alpha

- Functions Should Only Do One Thing*

Each function you create should only have one responsibility ideally. When you call a function and you are not getting the output you expect, it is hard to debug when it is 80 lines of code and a lot of values are being changed. It is better to break it up into a lot of smaller concise functions, and then call those in sequence. This makes it easy to change out those functions later on without updating any of the other logic. It also allows for you to see a high level overview of what a function does.

Example: 
private void PhysicsCalculations()
{
    CalculateVelocity();
    
    MoveBall();

    if (PlayerCanFall()())
    {
	DropPlayer();
    {
}


- State Independence

Try not to always rely on states


- Global Variables = Cringe

When there is a problem with a global variable that is being touched by 15 different function, it is almost impossible to find which function is causing the problem. It is best to not change the value of global variables across many different functions/scripts, instead just passing a read value. Global state is still very important for things that need to be access all across a script or read from other scripts, but limit how many access points you are giving to your variables.
